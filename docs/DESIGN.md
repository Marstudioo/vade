# Vade DESIGN.md — 随身终端设计法典

> 遵循 DESIGN.md 正典（Google Stitch / awesome-design-md 9 章节）+ 工程章节。
> 版本 v0.1（2026-11-08）。这是 UI 与产品实现的唯一事实源；改动走"先方案后实施"。

## 0. 产品定位

**Vade**（vade mecum，"与我同行"）= CardputerZero 上的随身终端：**离线知识库检索 + AI 对话 + 任务速览 + 外出采集 + 极简设置**。
场景：通勤（云梦台→新墩）、在家桌边、外出采集。设计信条：**配置归大屏，使用归小屏**。

## 1. Visual Theme & Atmosphere（视觉主题与氛围）

- 情绪：安静、可靠、陪伴感——不是仪表盘，是"口袋里的一位同伴"。
- 密度：中低。工作记忆有限（320×170），**一屏一任务**，信息分块呈现。
- 风格基因：对齐系统自带图标的**扁平贴纸语言**（粗圆描边、高饱和平涂）；界面本身深色优先（AI 产品横评 7/8 暗色优先）。
- 动效哲学：克制。仅焦点移动/页面切换 ≤150ms，无装饰动画（A53 软渲染红线）。

## 2. Color Palette & Roles（色板与语义角色）

| 角色 | 深色（默认） | 浅色 | 用途 |
|---|---|---|---|
| background | `#0B0D12` | `#F7F8FA` | 页面底色（可换，见 §15 设置） |
| surface/card | `#14171F` | `#FFFFFF` | 卡片、气泡、输入区 |
| primary/accent | `#4D6BFE` | `#3B5BDB` | 焦点、主操作、进度 |
| text-primary | `#E8EAF0` | `#1F2225` | 正文 |
| text-muted | `#8A90A0` | `#6B7280` | 摘要、时间、占位 |
| success/warn/error | `#3ECF8E` / `#F2C97D` / `#E88080` | 同系加深 | 状态语义 |
| border | `#2A2E3A` | `#E0E0E6` | 分隔、描边 |

规则：强调色**单一**（AI 产品横评结论）；正文对比度 ≥ WCAG AA；焦点行用 accent 描边而非整行变色。

## 3. Typography Rules（字体层级）

字体：思源黑（Noto Sans CJK，系统自带）为主；代码/等宽用 JetBrains Mono（有则用，无则 fallback）。

| 层级 | 字号 | 用途 |
|---|---|---|
| title | 16px bold | 页面标题栏 |
| body/chat | 15px | 对话正文、阅读正文（横评 15-16px） |
| ui | 14px | 列表标题、按钮、输入框 |
| caption | 12px | 摘要、时间戳、状态栏（下限，禁 10px） |

行高 1.4；阅读页行高 1.5 可调；CJK 禁止斜体，强调用色/粗。

## 4. Component Stylings（组件规格）

- **列表项**：2 行式（14px 标题 + 12px 摘要），行高 ~32px，焦点行 accent 描边 + 左侧指示条。
- **对话气泡**：圆角 8px，内边距 12px，消息间距 16px（横评基准）；用户右 accent 淡底、助手左 surface 底；**超长消息折叠尾部 + 展开**。
- **输入框**：底部固定，圆角 8px，焦点 accent 描边；发送键 22×22 图标。
- **按钮**：主按钮 accent 实底、次按钮描边；命中区 ≥24×24。
- **底部键位条**：5 图标 22×22，中心 x=49/105/161/217/273、y=153（官方坐标，勿动）。
- **Toast**：顶部滑入 ≤2s；**帮助浮层**：fn+H 每页键位表。
- **加载指示**：行内 spinner（12px），不做全屏遮罩。

## 5. Layout Principles（布局原则）

```
状态栏 20px（时间/电量/WiFi，图标用系统图标字形）
内容区 ~125px（页面自适应）
键位提示条 25px（5 图标 + 快捷键数字）
```
- 三段式固定；内容区内部滚动，**页面级不滚**。
- 留白哲学：边距 8px 网格；宁可少放一项，不压缩字号。
- 层级：hub（5 模块）→ 列表 → 详情，最多 3 级；Esc 逐级返回、长按回 hub。

## 6. Depth & Elevation（层次）

无阴影体系（软渲染费像素）；层次靠**表面色差 + 描边**表达：background < surface < 弹层（+1 级描边）。

## 7. Do's and Don'ts（正反例）

**Do**：一屏一任务；键盘路径优先；离线可用；手动触发一切同步；长列表虚拟化/分页；每页 fn+H 帮助。
**Don't**：透明叠加层；装饰动画；>150ms 过渡；10px 字；隐藏手势；自动 cron；单屏塞多任务；硬编码 /dev/fb0。

## 8. Responsive Behavior

单一目标设备 320×170（无断点）；**HDMI 外接 1080p 时内容居中放大 2×**（远期，external_display 权限）。

## 9. Agent Prompt Guide

新页面给编码 agent 的口令模板：
> "按 vade/docs/DESIGN.md §2-§5 实现 X 页：BaseScreen 派生，列表用 reactive 绑定，焦点 accent 描边，字体 14/15/12 三档，键盘 4~8 已被全局占用请用 fn 层。"

# 工程篇

## 10. 系统架构（分层）

```
┌─────────── UI 层（LVGL 9 MVVM）───────────┐
│ hub/检索/对话/任务/采集/设置 6 Screen        │
│ theme 系统 · 键位路由 · 帮助/Toast          │
├─────────── 服务层（src/service）───────────┤
│ search(FTS5) · chat(HTTP unary) · tasks    │
│ capture(libcamera/ASR) · sync(手动)        │
├─────────── 数据层 ─────────────────────────┤
│ SQLite：fts 索引 · 速记 · 设置 · 会话缓存    │
├─────────── 后端适配（Agent 适配层）───────────┤
│ A 纯API │ B 远程Agent（DSH/Hermes/OpenAI兼容/Anthropic/自定义）│ C 本机dsh裁剪  │
└────────────────────────────────────────────┘
```
内存预算（真机 352MB 实测基准）：系统 ~200 + UI 20-30 + 检索 32 + 后端（A:0 / B:0 / C:~200 裁剪版）。

## 11. 检索模块（M1 核心）

- **索引流水线**（宿主机）：Obsidian 导出 → jieba 预分词 → FTS5(unicode61) 索引 → 推送到设备。**设备只查询**（139MB jieba 峰值留在宿主机）。
- 查询：**防抖即搜**（2 字起，200ms 防抖，GoldenDict 模式）→ `snippet()/highlight()` 命中片段列表 → 阅读页。
- 过滤语法（Anki 式）：`tag:xxx`、`path:小说/`（**小说目录默认排除**，可改）。
- 阅读页：分页/滚动双模式、字号三档、进度书签、Esc 回列表保留查询。
- **向量查询决策**：本地嵌入模型在 352MB 上不可行（INT8+离线预计算才勉强）→ **Phase 2** 做"宿主机预计算向量 + 设备端 RRF 融合检索"（FTS5+向量+标签+时间衰减 4 路，Aetherius 方案）。Phase 1 纯 FTS5 已满足"实实在在查到"。

## 12. 对话模块

- **对话方式决策**：**HTTP unary**（`session/prompt` 提交 + `session/wait` 轮询），**不用 WebSocket**（11-07 实测定案：省一条长连接、断线恢复简单、512MB 环境友好）。
- **渲染三态**：待机（历史可读）→ spinner（行内）→ **流式分段渲染**（每次 wait 返回增量段，追加重排当前气泡）。
- **载入滚动**（你问的）：
  - 历史**向上无限加载**：触顶前 3 行预取上一页（20 条/页），顶部行内 spinner，**锚定阅读位置**（补载后 scroll offset 补偿，不跳页）。
  - 新消息**自动跟随到底**，但用户上翻阅读历史时**冻结跟随**，出现"↓ 新消息"角标，按 fn+↓ 回底。
  - 超长消息折叠尾部（>3 屏）+ 展开全文（进阅读页复用）。
- **本地 AI 决策**：本地 LLM 三重不可行（模型 1.3G/速度/部署绑定）——对话**永远走外置后端三态**；本地只做 sherpa-onnx 语音输入（Phase 2）。"内置本地 AI"降格为：**本地意图路由**（快捷指令/离线 FAQ 直答，不发后端）。
- 辅助：快捷指令模板（fn+数字）、重新生成、复制、token 计量条、错误重试。
- **Agent 适配器设计**（不绑定任何一家）：
  - 统一契约三动作：`send(prompt,history)→分段回复` / `fetch_board()`（可选）/ `push_note()`（可选）；不支持的能力自动隐藏。
  - 产品预设：**DSH 首选**（unary API 实测过）、Hermes（API/SSH）、OpenAI 兼容（一格覆盖 DeepSeek/智谱/qwen 等厂商）、**Anthropic Messages API**（`/v1/messages`，x-api-key + anthropic-version 头，SSE 事件流独立解析）；Gemini 走其 OpenAI 兼容端点或自定义。
  - **自定义接口**：连接方式（SSH 命令 / HTTP 模板）+ 提交模板 + 响应解析（JSON 路径/纯文本）+ 凭据本地文件 + 测试按钮。
  - 后端管理器多配置切换；当前激活项=状态栏 ☁️/📱/✈️ 指示（隐私路由执行器）。

## 12A. 语音交互设计（M3→M3.5，参考 cardputer-xiaozhi 实现）

**结论：可满足，分三级交付。**

**形态决策（先于一切实现）**：语音是**模态**不是应用。
① **语音输入（轻量转文字）**——ASR 结果注入现有输入框（对话/检索/速记），一套 ASR 服务喂三模块；
② **语音对话**——对话模块的语音 I/O 化，思考**永远在后端三态**，语音层不含智能；
❌ 不做独立语音助手/第二套对话系统（去重铁律）。

**网络×引擎矩阵与断网自动降级**：

| 场景 | ASR | TTS | 思考 | 状态栏 |
|---|---|---|---|---|
| 在线 | 云端 ASR | 云端 TTS | 三态后端 | ☁️ |
| 在线·本地偏好 | 本地 sherpa-onnx | 本地 Piper | 按后端 | 📱 |
| 断网 | **自动落本地 sherpa** | **自动落本地 Piper** | 不可用→降级 | ✈️ |

- 切换机制：连通性探测（启动+请求失败即切），ASR/TTS 统一引擎接口插拔，云端超时无缝落本地，不弹错打断。
- **断网降级链**：对话暂停 → 检索照常（FTS5 本地，语音"查XX"直达）→ 语音速记照常 → 本地意图路由（"打开设置/记一下"）照常。断网不是变砖，是变回工具。

| 级 | 能力 | 实现 | 延迟红线 |
|---|---|---|---|
| V1 语音输入（M3） | 形态①：说话→文字→注入输入框/速记卡 | 录音(pipewire/ALSA)→云端或本地 ASR→文本 | 转写显示 ≤2s（输入级，容忍度高） |
| V1.5 语音对话 | 形态②：说→后端想→TTS 答 | Opus→**独立 WS 音频流**（文本保持 unary）→服务端 VAD | 按下→首音 ≤1.5s |
| V2 离线语音链 | 断网自动降级全链 | sherpa-onnx KWS+SenseVoice int8 / Piper TTS（WeFlow 流程现成） | 唤醒 <300ms，全链 ≤3s |
| V3 完全体 | 全双工语音伴侣 | Module LLM（路径 C）KWS/ASR/LLM/TTS 全在模块 | 毫秒级唤醒 |

**XiaoZhi 的实现拆解（抄作业清单）**：
- 双向语音 = WebSocket + **Opus 编码**（省带宽/抗丢包）；push-to-talk（空格键）起步，**服务端 VAD** 判定说完；TTS 播完**自动再听**（连续对话模式）。
- 架构：C++ 主体 + Python 桥（`ws_bridge.py` 音频流、`display_bridge.py` PIL 渲染 framebuffer、`mcp_tools.py` 本地工具）；macOS 模拟器开发；CI 自动出 arm64 .deb。
- 好做法吸收：语音流用 WS 是**合理例外**（持续双向音频流正是 WS 的用例），文本对话仍 unary 不变——**混合传输**。
- 中文优先（记忆层证据）；语音音量/提示音走 miniaudio；fn+H 有语音键位表。

**延迟预算（知识库 07-09 实测，RPi5 基准，A53 更慢）**：唤醒 100-200ms + ASR 2-5s（whisper-base；SenseVoice int8 更快，A53 待实测）+ LLM 500-1000ms + TTS 300-500ms → 总 3-7s。
**压延迟四板斧**（必须全用）：流式 LLM（首 token 即 TTS）、分段 TTS（逐句合成播放）、本地唤醒/VAD、音频先行（先播"嗯…"占位）。

## 15A. 隐私与安全（数据路由铁律）

**原则：本地默认、云端显式、状态可见、绝无遥测。**

| 数据 | 敏感级 | 路由 | 铁律 |
|---|---|---|---|
| 语音（声纹+内容）| 高 | 默认本地 sherpa ASR；云 ASR 仅显式开启 | 语音不出设备为默认态 |
| 对话（含小说情节）| 高 | 默认后端 B（自家 Hermes）/C；A（云 API）显式选择 | B/C 是隐私安全区，不经任何第三方 |
| 检索词/知识库 | 最高 | **永不上传**（FTS5 全本地） | 架构保证；向量检索 Phase 2 同理（本地索引） |
| 速记/素材 | 高 | 本地 SQLite + 手动同步 | 手动触发铁律（ADR A7） |
| 遥测/崩溃 | — | **不存在** | 无第三方 SDK、无上报 |
| 诊断日志 | 中 | 本地导出，**脱敏**（去对话内容/密钥） | 分享前用户可见内容 |
| API 凭据 | — | 文件存储（WSL ~/.czdev 等），不进命令行/日志 | 用后轮换 |

- 传输一律 HTTPS/WSS；公共热点下仅用后端 B（自家）或离线态。
- 设置「隐私」组：逐功能云开关（对话/ASR/TTS 分开）、**离线优先模式**（一键全本地）、数据清除、诊断导出。
- 商店提交的演示视频只含演示数据；`uploader_email` 落 noreply（令牌勿勾 user:email，见 AGENTS.md）。
